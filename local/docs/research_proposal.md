# WorldLLM 연구 제안서

> LLM 기반 서사 IP 설정 자동 생성 및 일관성 유지 시스템의 설계와 검증
> *A System for Automated Narrative IP Lore Generation and Consistency Maintenance Using LLMs*

---

## 0. 문서 개요

본 문서는 WorldLLM 시스템의 연구 배경, 핵심 주장, 각 파트별 시험론(가설)과 검증론(측정 방법)을 정리한다.
현재 시스템은 **1차 개념 증명(Proof of Concept)** 단계이며, 이후 로컬 LLM 전환을 통한 대규모 검증으로 이어지는 2단계 로드맵을 전제로 한다.

---

## 1. 연구 배경 및 문제 제기

### 1-1. 로어(Lore)의 경제적 특성

서사 기반 미디어(게임, 웹소설, 드라마, 버추얼 IP 등)에서 **세계관 설정(Lore)**은 전형적인 비대칭 가치재다.

- **없으면 티난다** — 세계관이 얕다는 인상을 줌
- **있어도 대부분 소비되지 않는다** — 일반 유저/독자는 설정집을 정독하지 않음
- **그러나 코어 팬층과 IP 확장성에는 결정적** — 2차 창작, 파생 콘텐츠, 라이선싱의 근거

결과적으로 로어는 **흥행의 직접 변수가 아니지만 IP 장기 가치의 핵심 인프라**다.

### 1-2. 현재 산업의 구조적 문제

| 규모 | 현실 |
|------|------|
| 대형 스튜디오 | 로어 팀 별도 운영 또는 외주 → 비용 부담 |
| 중소 스튜디오 | 로어 전담 인력 없음 → 설정 최소화 또는 포기 |
| 1인 크리에이터 | 작가 본인 머릿속에만 존재 → 연재 길어지면 설정 붕괴 |

**핵심 병목:** 로어를 충분히 쌓고 관리할 인력이 없는 것이지, 로어가 필요 없는 게 아니다.

### 1-3. 연구의 출발점

> *"소규모에서도 깊이 있는 세계관을 구축할 수 있다면,
> 더 많은 IP가 파생 콘텐츠로 확장될 수 있다."*

이 문제의식에서 출발한 WorldLLM은 LLM을 **로어 생성 자동화 엔진**으로 활용하고,
소수의 인간 크리에이터가 **핵심 설정 설계 및 검수**에만 집중하는 구조를 제안한다.

## 2. 핵심 주장

### 주장 구조

```
[문제]
로어는 IP 가치에 필수적이지만 생산·관리 비용이 높아
소규모 제작 환경에서는 투자 결정이 어렵다.

[제안]
LLM 기반 자동 생성 시스템으로 양적 생산을 자동화하고,
크리에이터는 방향성 설계와 최종 검수에만 집중한다.

[기대 효과]
① 소규모 스튜디오/크리에이터도 대규모 세계관 구축 가능
② 설정의 DB화로 일관성 유지 비용 절감
③ 축적된 설정을 기반으로 IP 파생 확장 가능
④ 전담 인력 없이 검수 중심 소수 운영 가능
```

### 포지셔닝

> LLM이 시나리오 라이팅을 **대체**하는 것이 아니라,
> 크리에이터가 집필에 집중할 수 있도록 **설정 관리 부담을 증폭·위임**하는 것.

이 프레이밍은 업계 거부감을 낮추고 실용적 도입 논거를 강화한다.

---

**시험론 (H1)**
> LLM 보조 로어 생성 시스템은 인간 단독 작업 대비 동일 시간 내 유의미하게 많은 설정 엔트리를 생성할 수 있다.

**검증론**
- 인간 로어라이터 1인 × 1시간 생성 엔트리 수 vs 시스템 동일 시간 생성 수 비교
- 생성된 엔트리의 품질 평가: 동일 설정에 정통한 평가자가 블라인드로 "세계관에 적합한가" 5점 척도 평가
- 수용 가능 엔트리 비율(검수자가 수정 없이 채택한 비율) 측정

---

## 3. 시스템 설계 원칙과 연구적 의의

### 3-1. 틱(Tick) 구조 — 시간 축 위의 자율 진화

WorldLLM의 가장 독창적인 부분은 단발성 생성이 아닌 **틱 단위 반복 진화**다.

```
기존 연구: 프롬프트 → LLM → 설정 생성 (1회성)
WorldLLM:  Seed 설정 → 틱 1 → 틱 2 → ... → 틱 N (누적 진화)
```

각 틱은 직전까지의 모든 세계관 상태를 컨텍스트로 받아 새로운 사건을 생성하므로,
**인과관계가 시간 축 위에 축적**된다.

---

**시험론 (H2)**
> LLM은 틱이 반복될수록 누적된 세계관 설정과 인과적으로 일관된 사건을 생성하는 능력을 유지할 수 있다.

**검증론**
- 50틱 이상 실행 후 각 틱의 이벤트가 기존 엔트리 설정과 모순되는 빈도 측정
- 평가 기준: (a) 기존 엔트리 내용과 직접 충돌, (b) references 없이 기존 설정 무시, (c) 일관성 있는 파생
- 틱 구간별(1~10, 11~30, 31~50) 일관성 지수 변화 추이 분석
- `reasoning` 필드 분석: LLM이 기존 설정을 실제로 참조하고 있는가

---

### 3-2. Seed 데이터 설계 — 인간 크리에이터의 역할

유저가 설계한 Seed 엔트리는 `[🔒유저]` 태그로 보호되며 LLM이 직접 수정할 수 없다.
LLM은 이 Seed를 **기반**으로만 파생 엔트리를 생성한다.

이 구조는 연구적으로 **독립변수(Seed 설계)와 종속변수(생성 결과)의 명확한 분리**를 가능하게 한다.

---

**시험론 (H3)**
> Seed 데이터의 양과 구체성이 높을수록 LLM이 생성하는 설정의 내적 일관성과 풍부함이 증가한다.

**검증론**
- 동일 세계관 컨셉으로 Seed 조건 3단계 설계:
  - 조건 A: 엔트리 3개 (세계관명, 주요 세력 1, 주인공 1)
  - 조건 B: 엔트리 10개 (A + 부가 설정)
  - 조건 C: 엔트리 30개 (B + 상세 설정)
- 각 조건에서 동일 틱 수(30틱) 실행 후 비교:
  - 생성 엔트리 수 및 카테고리 분포 다양성
  - references 연결 밀도 (관계도 그래프 엣지 수)
  - 평가자 일관성 점수
- 실험 재현성: DB 백업/복원 기능으로 동일 Seed에서 3회 반복 실행 가능

---

### 3-3. 3-레벨 프롬프트 — 방향성 제어 메커니즘

```
Level 1: 세계관 기반 법칙 (불변 규칙)
Level 2: 시대/맥락/현재 상황 (현재 조건)
Level 3: 틱 진행 규칙 (변화 강도, 금지 행동)
```

이 계층적 구조는 **크리에이터가 LLM의 생성 방향을 어느 정도 제어할 수 있는가**를 실험할 수 있는 장치다.

---

**시험론 (H4)**
> 3-레벨 계층 프롬프트 구조는 단일 프롬프트 대비 LLM 세계관 생성의 방향성 제어 효과가 유의미하게 높다.

**검증론**
- 동일 Seed에서 조건 3가지 비교:
  - 조건 X: 프롬프트 없음 (Level 1~3 전부 "없음")
  - 조건 Y: 단일 프롬프트 (기존 방식, 자유 서술 1개)
  - 조건 Z: 3-레벨 구조 (Level 1~3 모두 설정)
- 크리에이터가 사전에 명시한 "의도한 방향" 목록을 기준으로, 각 조건의 생성 결과가 의도와 일치하는 비율 측정
- LLM-as-Judge 방법론 적용 가능 (GPT-4/Claude에게 의도 일치 여부 평가 위임)

## 4. 미디어 믹스 확장 가능성

### 4-1. 공통 구조 분석

모든 서사 미디어는 동일한 근본 문제를 공유한다.

```
공통 문제:
① 설정 양 증가 → 일관성 유지 비용 급증
② 핵심 설정이 소수 크리에이터의 머릿속에만 존재
③ IP 확장 시 설정 재구축 비용
④ 공동 작업 환경에서 설정 충돌

WorldLLM의 공통 가치:
① 설정의 DB화(외재화)로 접근·관리 가능
② LLM이 기존 설정 참조하며 일관성 있게 확장
③ references 구조로 인과관계 추적
④ 유저 Seed 보호로 핵심 설정 보존
```

---

### 4-2. 분야별 적용 시나리오

#### 웹소설 / 장편 소설

**변조 포인트**

| WorldLLM 현재 | 웹소설 적용 |
|--------------|------------|
| 틱 = 시간 단위 | 틱 = 챕터 / 아크 단위 |
| 엔트리: 세계관 요소 | 엔트리: 인물 / 장소 / 사건 / 복선 |
| 이벤트: 세계관 변화 | 이벤트: 플롯 포인트 발생 |

**핵심 가치:** 연재 장기화로 인한 **설정 붕괴 방지**.
시스템의 유저 엔트리 보호 메커니즘이 "작가가 1화에 심은 설정이 100화에도 유지"되는 구조를 지원한다.

---

**시험론 (H5)**
> WorldLLM 기반 설정 관리 시스템은 장편 연재 환경에서 설정 충돌(모순) 발생 빈도를 유의미하게 감소시킨다.

**검증론**
- 동일 플롯 개요를 기반으로 두 조건 비교:
  - 조건 A: 시스템 미사용 (일반 집필)
  - 조건 B: WorldLLM으로 설정 DB 유지하며 집필
- 50챕터 분량 생성 후 설정 전문가가 모순 항목 수 카운팅
- 작가(피험자)의 설정 검색 소요 시간 측정

---

#### 드라마 / 시리즈 바이블 제작

**변조 포인트**

| WorldLLM 현재 | 드라마 적용 |
|--------------|------------|
| 틱 = 시간 단위 | 틱 = 에피소드 |
| 엔트리 카테고리 6종 | 인물 / 장소 / 관계 / 복선 / 세계관 규칙 / 사건 |
| LLM이 세계관 진화 | LLM이 에피소드별 인물 상태·관계 변화 추적 |

**핵심 가치:** 다중 작가 환경에서 **시리즈 바이블 일관성 자동 관리**.
현재 수백 페이지짜리 수작업 문서를 대체하고 지속 갱신을 자동화한다.

---

**시험론 (H6)**
> LLM 기반 시리즈 바이블 시스템은 다중 작가 공동 집필 환경에서 설정 충돌 조율 비용을 감소시킨다.

**검증론**
- 시나리오 작가 그룹(3~5인)을 대상으로 비교 실험:
  - 조건 A: 기존 방식 (공유 문서로 바이블 유지)
  - 조건 B: WorldLLM 사용
- 설정 충돌 발생 건수, 조율 소요 시간, 작가 인지 부하(NASA-TLX 설문) 측정

---

#### 버추얼 유튜버 / 2D 아이돌 IP

**변조 포인트**

| WorldLLM 현재 | 버추얼 IP 적용 |
|--------------|--------------|
| 세계관 엔트리 | 캐릭터 설정 / 세계관 규칙 / 관계도 |
| 틱 = 시간 진행 | 틱 = 콘텐츠 시즌 / 이벤트 |
| 새 엔트리 생성 | 새 캐릭터 추가 시 기존 설정과 호환되는 배경 자동 생성 |

**핵심 가치:** 팬 커뮤니티가 설정을 파고들고 2차 창작을 생산하는 구조에서
**일관된 설정 확장**이 IP 생태계 유지의 핵심이다.

---

**시험론 (H7)**
> LLM 기반 IP 설정 확장 시스템은 기존 설정과 신규 추가 설정 간 일관성을 유지하면서 설정 생성 속도를 향상시킨다.

**검증론**
- 기존 캐릭터 설정 20개가 있는 조건에서 신규 캐릭터 10개 추가:
  - 조건 A: 인간 설정 작가가 기존 설정 참고하며 수작업
  - 조건 B: WorldLLM references 기능 활용
- 소요 시간, 기존 설정과의 충돌 수, 팬 평가자(10인)의 자연스러움 점수 비교

## 5. 연구 로드맵

### 1차 검증 — 현재 단계 (API 환경)

**목적:** 개념 증명. 시스템이 동작하고 측정 가능한 결과를 낼 수 있음을 입증.

| 검증 항목 | 측정 방법 | 기대 결과 |
|---------|---------|---------|
| 생산성 우위 | 인간 1인 1시간 vs 시스템 동일 시간 엔트리 수 | 양적 우위 입증 |
| 일관성 유지 | 50틱 이후 모순 이벤트 비율 | 자율 진화 가능성 입증 |
| 검수 부하 | 수정 없이 채택 가능한 엔트리 비율 | 소수 검수 현실성 입증 |
| 방향성 제어 | 3-레벨 프롬프트 유무 조건 비교 | 제어 메커니즘 유효성 입증 |

**한계 인정:** API 비용 제약으로 틱 수와 반복 실험 횟수에 한계가 있음.

---

### 2차 검증 — 로컬 LLM 전환 후

**목적:** 대규모 검증. API 비용 제약 없이 장기·반복·대규모 실험 수행.

| 확장 실험 | 내용 |
|---------|------|
| 장기 진화 | 200틱 이상 실행, 설정 일관성 장기 추이 분석 |
| 병렬 실험 | 동일 Seed로 동시 10개 실험 → 통계적 유의성 확보 |
| 모델 비교 | 모델 크기/종류별 생성 품질 비교 (연구 변수 확장) |
| 미디어 적용 | 게임 외 웹소설/드라마 바이블 적용 실험 |

**전환 비용:** `llm_client.py`의 `get_llm_client()` 함수 단 한 곳만 수정.

---

### 3차 연구 — 산업 협력 단계

**목적:** 실제 제작 환경에서의 유효성 및 경제성 검증.

```
실제 소규모 스튜디오와 협력
→ 신규 IP 개발 과정에 시스템 도입
→ 로어 생산 비용, 품질, IP 활용도 전후 비교
→ "AI 보조 설정 파이프라인의 경제성 모델" 제시
```

## 6. 연구의 한계 및 범위 설정

솔직한 한계를 명확히 설정하는 것이 연구의 신뢰성을 높인다.

### 이 시스템이 할 수 없는 것

| 항목 | 이유 |
|------|------|
| 감정선과 서사 장력 | "이 장면에서 독자가 울어야 하는" 순간 설계는 별개 문제 |
| 의도적 복선 설계 | 1화 복선 → 50화 회수 구조는 틱 방식으로 사전 설계 불가 |
| 문체와 톤 | 설정 생성과 실제 원고 집필은 다른 레이어 |
| 창작 의도의 대체 | 크리에이터의 주관적 비전은 시스템이 제안할 수 없음 |

### 따라서 본 연구의 범위

> **"시나리오 라이팅 대체"가 아닌**
> **"IP 설정 관리 및 확장 지원 도구"**로서의 유효성 검증

이 범위 설정은 업계 거부감을 낮추고 실용적 도입 논거를 강화한다.
